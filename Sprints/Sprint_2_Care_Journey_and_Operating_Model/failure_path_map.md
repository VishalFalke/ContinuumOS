# Sprint 2 — Failure-Path Map

## Safety rule

The operating pattern is: **uncertain data → exception queue → human reconciliation → verified safe return**. It must never become uncertain data → silent attachment → normal workflow progression.

The map is for the synthetic Asha Mehta episode (`SYN-PAT-1001`). Exception states are canonical. Cancellation/no-show, test-not-performed, provider rejection, result-never-arrives and stale work are reason-coded handling around existing states unless a listed exception state is evidenced.

## Cross-cutting recovery rule

`Integration Unavailable` recovery returns the episode to the **last verified valid state**, not automatically to the intended next state. A restored service must not replay an unverified action or advance the episode twice. Any resumed write or state transition requires verified source data, idempotent handling where applicable and an auditable human or system reconciliation record.

AI-support unavailability does not by itself make the required source or workflow service unavailable. It is a non-blocking assistive-service failure: record it, use source evidence and continue the authorised human workflow.
